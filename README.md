# mktlink

Сервис «ссылка на товар → канонический URL + название + продавец» для **Ozon,
Wildberries и Яндекс.Маркета**.

Репозиторий раньше держал батч-скрейпер цен на детское питание (19 магазинов,
прогон раз в сутки, выгрузка в XLSX и Google Sheets). Он удалён: это была
другая задача — категорийный листинг с браузером на каждый прогон, а здесь
одна карточка за фиксированный бюджет.

Из него переиспользовано **знание**, а не код, и каждое переиспользование
подписано в docstring'е соответствующего модуля со ссылкой на файл и строку
удалённого кода. Два его отказа, объясняющие, почему наши функции устроены
иначе, сохранены как исполняемые эталоны в `tests/legacy_reference.py` — они
проверяются тестами, а не пересказываются в комментарии. Сам код доступен в
истории git до коммита `841dac3`.

## Что это делает

```http
POST /v1/product
{"url": "https://ozon.ru/t/AbC123"}
```

```json
{"status": "ok",
 "url": {"submitted": "https://ozon.ru/t/AbC123",
         "canonical": "https://www.ozon.ru/product/smes-1234567890/", "hops": 2},
 "product": {"name": "Смесь Nutrilon 1", "sku_id": "1234567890"},
 "seller": {"name": "ООО «Ромашка»", "kind": "third_party", "status": "resolved",
            "source": "ozon:state:webCurrentSeller-4422.name"}}
```

Короткие ссылки из мобильных приложений раскручиваются до настоящего URL.
Прокси покупаются, продлеваются и заменяются автоматически через proxy6.net.

## Четыре ограничения, из которых выведено всё остальное

1. **Три маркетплейса.** Всё остальное отвечает `422` за единицы миллисекунд.
2. **2–3 запроса в минуту.** Не в секунду. Отсюда один файл SQLite вместо
   Postgres с Redis, min-interval guard вместо токен-бакетов и отсутствие
   очередей, сброса нагрузки и сайзинга по закону Литтла.
3. **Пул не закупается впрок.** На старте переиспользуем купленное, иначе
   покупаем ровно один адрес. Растём только заменой.
4. **Потолок ответа — параметр**, `MKTLINK_RESPONSE_BUDGET_MS`, диапазон
   5000…15000, по умолчанию **15000**.

### Почему дефолт 15000, а не 5000

При таком потоке на произвольных пользовательских ссылках попадание в
продуктовый кэш близко к нулю: почти каждый запрос холодный по товару. Тёплой
остаётся только сессия, и держится она фоновым обновлением, а не трафиком.

Обычный запрос при тёплой сессии идёт за 0.7–1.5 с при любой настройке ручки.
15 секунд покупают не скорость, а возможность **дождаться** идущего минтинга
вместо ответа `202`: минтинг по замерам репозитория стоит 9–19 с, и в 5 секунд
он не помещается ни при каких условиях.

Посмотреть, что ручка делает с лестницами:

```bash
mkt budget --budget-ms 5000
mkt budget --budget-ms 15000
```

## Что достижимо, а что нет

proxy6.net продаёт **датацентровые** IPv4, и это главное ограничение.

**Все три строки — замер, а не оценка.** Проверено 2026-09-03 на живых
ссылках через купленный IPv4 Shared от proxy6.

| | достижимость | замер |
|---|---|---|
| **Wildberries** | **РАБОТАЕТ** | `card.wb.ru/cards/v4/detail`, HTTP 200 без cookie и без браузера. Название и продавец получены: `BASKEY`, `supplierId=55588`. 571 мс холодный запрос, 1 мс из кэша |
| **Ozon** | **НЕ достижим** | 403 и curl_cffi, и Camoufox 152 с `geoip=True`, на главной и на карточке. Адрес в блок-листе — подробности ниже |
| **Яндекс.Маркет** | **НЕ достижим** | 302 → `/showcaptcha` («Вы не робот?»). Одинаково с cookie и без, одинаково curl_cffi и Camoufox |

Остальные магазины не предлагаются и не будут: ServicePipe не пробивается из
датацентра ни stealth-браузером, ни платным scraping-API — это доказано
четырьмя откатами в истории репозитория (`addfdc5 → 62b049f` и
`b50ab72 → 841dac3`, оба возврата).

### Замер по Я.Маркету: SmartCaptcha, и лёгкий jar не помогает

| попытка | результат |
|---|---|
| `curl_cffi` без cookie | `302` → `/showcaptcha?cc=1`, ставит `yandexuid` и `spravka` |
| `curl_cffi` + лёгкий jar с главной | `302` → `/showcaptcha`, то же |
| Camoufox 152 через прокси | `200` на `/showcaptcha`, заголовок «Вы не робот?» |

Челлендж приходит **на том же хосте** `market.yandex.ru`, поэтому проверка
хоста его пропускает — ловит только путевое veto, ради которого оно и
написано. Без него раскрутчик объявил бы страницу капчи каноническим URL.

Вывод дизайна подтверждён: для Я.Маркета это **челлендж, а не репутация
адреса**, и эскалация тарифа v3 → v4 его не решает. Нужно либо решать капчу,
либо резидентный адрес.

### Замер по Ozon от 2026-09-03: не достижим с датацентрового адреса

Проверено на живой ссылке из мобильного приложения через купленный
IPv4 Shared от proxy6:

| попытка | результат |
|---|---|
| `curl_cffi` без cookie | `307` + `Set-Cookie: __Secure-ETC`, затем `403` |
| Camoufox 152 через прокси | `403`, заголовок «Похоже, нет соединения» |
| Camoufox 152 + `geoip=True` | `403`, то же — и на главной, и на карточке |
| Camoufox 152 **без** прокси | `403`, но заголовок **«Antibot Captcha»** |

Последняя строка — самая важная. **Через датацентровый адрес Ozon отвечает
ХУЖЕ, чем без прокси:** напрямую он предлагает челлендж, а через прокси
маскирует отказ под сетевую ошибку и челленджа не предлагает вовсе. Значит
адрес не «недоверенный», а в блок-листе, и качество отпечатка тут ни при чём.

Прямое следствие: **эскалация тарифа v3 → v4 у Ozon задачу не решает** —
выделенность адреса не меняет его принадлежность датацентру. Чтобы Ozon
заработал, нужны российские резидентные прокси от другого поставщика; это
смена поставщика, а не правка кода.

Конвейер минтинга при этом отработал правильно и ничего не соврал: Camoufox
снял cookie за 9788 мс (оценка дизайна была 9–19 с), сверка отпечатка прошла,
`verify_replay` дал 403 — и jar **не был опубликован**. Сервис отвечает
`202 pending` с каноническим URL, а не выдуманными данными.

### Что здесь не замер, а гипотеза

Формы коротких ссылок, пути к продавцу и антибот-вердикты помечены в коде как
гипотезы. Пока путь не снят с живой карточки, лейн честно отдаёт
`seller_status = unknown_layout` — это правильное поведение, а не поломка.

```bash
mkt selectors     # покажет, кто ещё работает на догадках
```

Самая крупная непроверенная ставка: весь тёплый путь стоит на том, что
Camoufox-jar переигрывается через `curl_cffi`. На Ozon проверить её не
удалось — там блокируется сам адрес, до всякого отпечатка. Остаётся
проверить на Wildberries и Я.Маркете.

Попутно выяснилось, что **точного совпадения версий не бывает**: Camoufox —
это Firefox 152, а самая новая цель curl_cffi 0.16.3 — `firefox147`. У двух
инструментов независимые циклы релизов, поэтому сверка проверяет
совместимость с названным допуском (`MAX_MAJOR_GAP = 8`), а не равенство.
Первая редакция требовала равенства и заблокировала бы минтинг целиком.

## Устройство

```
mktlink/                 # ЕДИНСТВЕННЫЙ пакет репозитория
├── constants.py     физика (DNS, TCP, накладные) — от ручки не зависит
├── budget.py        всё, что от ручки зависит; тождество Σcap+Σguard+резидуал == NET
├── timing/          один абсолютный дедлайн, каждый таймаут — срез от остатка
├── urls/            реестр, валидация, SSRF, раскрутка, каноникализация
├── egress/          curl_cffi, отпечаток, jar, гард спейсинга
├── extract/         normalize (копия), сканер JSON, якорный поиск продавца
├── marketplaces/    вердикты, селекторы, три лейна, проход по лестнице
├── proxy6/          клиент, ошибки, кодек descr, чистый планировщик
├── store/           SQLite: 18 таблиц, денежные потолки триггерами
└── api/             схемы, ошибки, оркестратор, приложение
```

Два процесса: `api` обслуживает запросы, `forge` держит браузер и владеет
proxy6. Разделение — единственная проверяемая в CI формулировка запрета
браузера на пути запроса: в образе `api` нет ни `camoufox`, ни `playwright`,
поэтому браузер там не импортируется, потому что его там нет.

## Запуск

```bash
uv venv && uv pip install -e ".[dev]"     # путь запроса, без браузера
mkt init-db
uvicorn mktlink.api.app:create_app --factory
```

Процесс `forge` ставится отдельным окружением — так запрет браузера на пути
запроса становится свойством упаковки, а не соглашением:

```bash
uv pip install -e ".[forge]" && python -m camoufox fetch
```

```bash
pytest          # 492 теста; конфиг в pyproject.toml
ruff check .
```

## Что надо сделать до первой строки продакшена

Phase 0 — блокирующий гейт, а не разминка. Три замера, около 40 ₽:

1. Снять живой payload карточки Ozon и Я.Маркета, запинить пути к продавцу.
2. Три карточки с датацентрового IPv4, по 20 попыток за три дня: доля капчи,
   молчаливой пустоты и успеха. Это превращает таблицу выше из ожидания в
   замер.
3. Расшарить карточку из мобильных приложений и записать реальные хосты
   коротких ссылок.

Пункты 1 и 3 блокирующие: без них лейн отдаёт `unknown_layout` на каждом
запросе, а короткие ссылки распознаются по угаданным формам.
